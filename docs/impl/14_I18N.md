# 14. Languages

**Goal:** the whole app and the voice assistant work in **English and Spanish** (required). French, German and Italian are a nice-to-have, added without touching code.
**Read first:** guide 04 (HUD), guide 07 (voice), guide 08 (agents).
**Plan tasks:** 49 (EN + ES), 50 (FR, DE, IT).
**Location:** `shared/src/i18n/`.

## Scope

| Surface | EN + ES (required) | FR, DE, IT (nice-to-have) |
|---------|--------------------|---------------------------|
| HUD, menus, alerts, base cards, provenance panel, phone page | Dictionary | Dictionary generated by the model, then reviewed |
| Voice input | Web Speech locale | Web Speech locale |
| Local critical commands | Hand-written patterns | Hand-written patterns (few words; write them, do not generate) |
| Agent replies | Model answers in the active language | Same |
| Voice output | Neural voice per language (guide 07) | Same, once a voice is chosen |
| Guardian verdict reasons | i18n key from rules; judge writes in the active language | Same |
| Code, comments, logs, docs, README | English only | — |

## Code

`shared/src/i18n/index.ts`:

```ts
export const LANGS = ["en", "es", "fr", "de", "it"] as const;
export type Lang = (typeof LANGS)[number];

/** Locale used for speech recognition (Web Speech API). */
export const ASR_LOCALE: Record<Lang, string> = { en: "en-US", es: "es-AR", fr: "fr-FR", de: "de-DE", it: "it-IT" };
/** Locale used for neural speech synthesis. Must match the list accepted by /api/tts. */
export const TTS_LOCALE: Record<Lang, string> = { en: "en-US", es: "es-US", fr: "fr-FR", de: "de-DE", it: "it-IT" };
export const LANG_NAME: Record<Lang, string> = { en: "English", es: "Español", fr: "Français", de: "Deutsch", it: "Italiano" };

type Dict = Record<string, string>;
const dicts: Partial<Record<Lang, Dict>> = {};
let active: Lang = "en";
const listeners = new Set<(l: Lang) => void>();

export function registerDict(lang: Lang, dict: Dict): void { dicts[lang] = dict; }
export const getLang = (): Lang => active;
export const availableLangs = (): Lang[] => LANGS.filter((l) => dicts[l]);

export function setLang(lang: Lang): void {
  if (!dicts[lang]) return;
  active = lang;
  for (const fn of listeners) fn(lang);
}
export function onLangChange(fn: (l: Lang) => void): () => void { listeners.add(fn); return () => listeners.delete(fn); }

/** Translate a key. Falls back to English, then to the key itself, so a missing string is visible but never breaks the UI. */
export function t(key: string, params: Record<string, string | number> = {}): string {
  const s = dicts[active]?.[key] ?? dicts.en?.[key] ?? key;
  return s.replace(/\{(\w+)\}/g, (_m, k) => String(params[k] ?? `{${k}}`));
}

/** Numbers follow the active locale; units stay SI and are never translated. */
export const fmt = (n: number, digits = 1): string => n.toLocaleString(ASR_LOCALE[active], { maximumFractionDigits: digits, minimumFractionDigits: digits });
```

`tools/i18n_generate.ts` (nice-to-have languages):

```ts
/** Generates fr/de/it dictionaries from en.ts with the language model. Output is committed and reviewed, not produced at runtime. */
import { writeFileSync } from "node:fs";
import { en } from "../shared/src/i18n/en.js";
import { chat } from "../server/src/llm/provider.js";

const TARGETS = { fr: "French", de: "German", it: "Italian" } as const;

for (const [code, name] of Object.entries(TARGETS)) {
  const msg = await chat("medium", [
    { role: "system", content: `Translate UI strings for a spaceflight mission console into ${name}. Return JSON with exactly the same keys.
Keep placeholders like {t} unchanged. Keep unit symbols, product IDs, agent names in capitals (BASE, GUARDIAN) and acronyms (EVA, O2, CO2) unchanged.
Use the terminology a space agency would use. Short strings must stay short: they sit on a helmet display.` },
    { role: "user", content: JSON.stringify(en) },
  ], { json: true, maxTokens: 4000 });
  const out = JSON.parse(msg.content ?? "{}") as Record<string, string>;
  const missing = Object.keys(en).filter((k) => !(k in out));
  const brokenPlaceholders = Object.entries(en).filter(([k, v]) => (v.match(/\{\w+\}/g) ?? []).some((p) => !out[k]?.includes(p))).map(([k]) => k);
  if (missing.length || brokenPlaceholders.length) throw new Error(`${code}: missing ${missing} / placeholders ${brokenPlaceholders}`);
  writeFileSync(`shared/src/i18n/${code}.ts`, `export const ${code} = ${JSON.stringify(out, null, 2)} as const;\n`);
  console.log(code, "ok", Object.keys(out).length, "strings");
}
```

## Instructions for the coding agent

1. **English is the source language.** `en.ts` holds every user-facing string. `es.ts` is written by hand with the same keys (the team is Spanish-speaking: have the user review it). A unit test fails if any dictionary lacks a key that exists in `en.ts` or drops a placeholder.
2. **No hard-coded visible text anywhere.** Elements carry `data-i18n="<key>"`; a small binder sets their text and re-runs on `onLangChange`. Dynamic strings call `t()`.
3. **Language selection:** "Language" menu item listing `availableLangs()`. Initial language from `?lang=`, then `navigator.language`, then English. Changing it updates, in one place: the dictionaries, `listener.lang` (through `ASR_LOCALE`), `radio.lang`, the `lang` sent with every agent request, and the `lang` parameter in the phone QR URL.
4. **Agents:** every system prompt ends with the reply language. Tool descriptions and prompts stay in English: models follow them reliably in English and answer in the requested language. Scientific product names and IDs are never translated.
5. **Guardian reasons:** rule verdicts return an i18n key plus parameters (`{ key: "guard.slope", params: {...} }`) and the browser renders them. The judge writes its free-text reason in the active language.
6. **Voice commands:** `LOCAL_INTENTS` patterns per language. English and Spanish now. For French, German and Italian write the handful of safety words by hand (emergency, abort, stop) and test them aloud.
7. **Nice-to-have phase (task 50):** run `npx tsx tools/i18n_generate.ts`, commit the three files, register them, choose a neural voice for each (guide 07, step 2) and smoke-test one full voice exchange per language. If a language has no good voice or recognition is poor, leave it out of `availableLangs()` instead of shipping it half working.
8. Numbers use `fmt()`; units stay SI in every language.
9. The README stays in English. Add one line listing the supported interface and voice languages.

## Acceptance criteria

- Switching between English and Spanish changes every visible string, the recognition language, the reply language and the voice, with no reload.
- The dictionary test passes: same keys and placeholders in every registered language.
- No Spanish text remains in code, comments or docs.
- Any nice-to-have language that appears in the menu completes a full voice exchange.
